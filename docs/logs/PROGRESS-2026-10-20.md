# Progress — 20 October 2026

## PostgreSQL development database

- Switched the default Docker database service from MariaDB to PostgreSQL 17 with a persistent `postgres_data` volume and host port `5433`.
- Added a health check so Laravel waits for PostgreSQL readiness, and enabled the PHP PDO PostgreSQL extension in the backend image.
- Updated the backend environment example and project/security documentation for PostgreSQL connection settings.
- Removed the legacy MariaDB service and its volume declaration from Docker Compose; PostgreSQL is now the only configured database service. Existing MariaDB records were not copied to PostgreSQL.
- Removed PDO MySQL from the backend image; it now installs PDO PostgreSQL only.
- Removed MySQL and MariaDB connections from Laravel's database configuration.
- Aligned Compose's default PostgreSQL password with `backend/.env.example`; a root `.env` `POSTGRES_PASSWORD` override must still match `backend/.env`'s `DB_PASSWORD`.
- Transferred all populated application data from the old MariaDB database: two accounts not already present in PostgreSQL, one household, one resident, and five activity logs. The existing PostgreSQL superuser was retained for the matching old account; user references were remapped and checked.
- Did not transfer old database cache, sessions, migration bookkeeping, or Sanctum access tokens; those are environment-specific or authentication state, so users need to sign in again.
- Verified PostgreSQL counts and account/household/log references, then removed the temporary MariaDB container and old MariaDB volume. Private pre-import dumps of both databases were saved under `/tmp` with mode `0600`.
- Removed a MySQL-only column ordering modifier from the user archive migration.
- Database migration and runtime verification remain pending; no tests or builds were run.
